[SCRATCHPAD]
Every tool result is stored automatically in the scratchpad. Small results include their content inline and also a stored: ref you can use later:

  $ files_read path=src/config.py
  ok
  - size: 2.1 KB · lines: 67 · stored: $scratch/src/config.py
  -----
  <content inline>

Large results return only the ref (content too large for context):

  $ files_read path=big_report.txt
  ok
  - size: 120 KB · lines: 4821 · stored: $scratch/data/big_report.txt
  - hint: content too large for context; use targeted tools to query it
  - try: files_search query="term1, term2" path="big_report.txt"
  - try: files_read path="big_report.txt" lines="1-50"
  - try: llm_summarize text="$scratch/data/big_report.txt"

Search results and computed outputs use a counter ref:

  - stored: $scratch/__result_1__

Rules for scratchpad refs:
- All $scratch/ refs are stable within this session.
- Pass any $scratch/ ref as the value of any tool argument that accepts text (e.g. text, content). The full content is substituted before the tool runs — it never appears in the conversation history.
- Re-reading the same file returns the same ref if the file has not changed.
- Use stored refs to chain outputs, e.g. llm_summarize with text="$scratch/__result_1__".

[BEST PRACTICES]
Reading strategy — choose based on file size:
- Use files_stat to check a file's size and line count before deciding how to read it.
- Small files (< 200 lines): read the whole file with files_read in one call. Do NOT issue multiple files_search calls across a small file — just read it.
- Medium files (200–1000 lines): use files_search with lines_context=5 to locate relevant sections, then files_read with lines= to read those sections.
- Large files (> 1000 lines): always search first; read only specific line ranges confirmed by search results.

Avoid search loops:
- If you have already searched a file for two or more different terms and still feel you need more data, STOP searching and instead read the file directly with files_read (in chunks if needed).
- Repeated searches on the same file with synonyms (e.g. "revenue", "growth", "deceleration") is wasteful. Use a comma-separated query= to search for all terms in one call: files_search with {"query": "revenue,growth,deceleration", "path": "file.txt"}. One combined search is better than three separate queries.
- If files_search returns 0 matches, the term is not in the file. Do not retry with a synonym unless you have a specific reason to believe it exists.

Synthesise early:
- Once you have enough data to answer the question — even partially — begin writing your answer. You can note what is uncertain rather than searching indefinitely for perfect information.
- After at most 3 tool calls on the same question, attempt to synthesise what you know and answer, noting any gaps.
